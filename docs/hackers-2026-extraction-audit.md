# Hackers 2026: a hand audit of the March fleet extraction

Written 2026-11-03 for the Hackers talk (Saturday 2026-11-07). It answers the question the Codex critique of the talk left open (`docs/reviews/2026-11-03-codex-talk-critique.md`, section 4.3): the registry and flight checks in `docs/hackers-2026-scrape-facts.md` measure consistency, not accuracy. For a representative sample of schools, did the model extract the right aircraft, attach the right rate and identify the right school, and what did it miss?

Sampling and scoring: `research/FlightSchoolMapping/scripts/probes/extraction_audit.py`. The hand labels are in that file, one entry per sampled school, so the numbers below can be recomputed and any label rechecked against the cached page.

> **Headline.** On the pages it was given, the model's tails are right 91% of the time and it missed none of the 68 the pages showed: 68 of 75 correct (Wilson 95% interval 82-95%), recall 68 of 68 (95-100%). Six of the seven false tails come from one site whose pages reached the model empty, so it read six tails out of URLs; those six were aircraft sold years ago. The other one is a simulator's ID. Of the 55 hourly rates it returned, 52 are the number posted for that aircraft (85-98%). One was copied from the aircraft listed above it, and two are simulator prices. It never filed a dry price as wet. In 15 calls that returned no fleet, it missed none: 7 sites list no aircraft, 4 were unreadable and 4 were the wrong site.

> **Correction to a working assumption.** The bigger error comes before the model reads anything. 09a's HTML cleaner (`clean_html`) removes any element whose class or id contains words like "sidebar" or "widget". On many sites that matches the `<body>` tag or a page-wide wrapper, and the whole page goes with it. In the sample, 7 of the 20 HTTP-pass calls got empty or title-only pages, and in at least 4 of them the raw HTML had fleet or price text the model never saw. Across the HTTP crawl, 812 of 1,992 schools with real page text (41%) kept under 5% of it after cleaning; in 503 of them a `<body>` class or id matches the filter (`extraction_audit.py body-loss`). The browser pass went back to 799 of those 812, so the merged dataset recovers most of them, but the HTTP pass on its own lost a lot. The browser pass also caps each page at 40,000 characters, not 50,000.

## 1. Method (written and committed before any sampled result was read)

**Unit.** One model call: a (pass, `custom_id`) pair from `output/fleet_extract_results.jsonl` (HTTP pass, 09b) or `output/fleet_browser_extract_results.jsonl` (browser pass, 09c) whose result succeeded and parses as JSON. A school read by both passes can appear twice; each call is scored against the pages that call saw. Errored and unparseable calls produced nothing and are outside the pool (98 errored and 2 unparseable HTTP calls, 3 unparseable browser calls, per `docs/hackers-2026-scrape-facts.md`).

**Strata.** F: the model returned at least one fleet entry. E: it returned an empty fleet. Target 25 from F and 15 from E, 40 in all.

**Draw.** Seed `20261107`. For each stratum, list its calls sorted by (pass, custom_id), shuffle with `random.Random(20261107)` (F first, then E, same generator), and walk the shuffled list, taking each call whose school can be identified (next paragraph) until the target is met. Calls skipped as unidentifiable are listed in the results with the reason. No call is dropped for any other reason once drawn.

**Which school and which pages each call saw.**
- Browser pass: `output/fleet_browser_extract_index.json` maps `custom_id` to domain explicitly. Checked: in 930 of 950 calls with a cited `source_url`, the cited domain equals the indexed domain, and the other 20 differ only in letter case. 09c built each prompt from every `.txt` file in `output/fleet_browser_text/<domain>/`, sorted by name, skipping files under 50 characters after stripping whitespace, each capped at **40,000** characters (not 50,000: that cap is 09b's). No file in that directory is newer than the results file.
- HTTP pass: the positional mapping is broken. `custom_id` `school_NNNN` was the position in the crawl index the batch was built from on 2026-03-10 (ids run to `school_3114`), but the index on disk has 2,958 entries and is byte-identical to the 2026-03-05 commit. Only 19 of 978 calls with a cited `source_url` match the entry at their position. The order is preserved with insertions and deletions, so the offset (`custom_id` number minus position on disk) drifts slowly. Rule for a sampled HTTP call, in order: (a) the majority domain of its cited `source_url`s, if that domain is in the index; else (b) the domain of its contact email, if that domain is in the index; else (c) the index entry whose `school_name` best matches the model's `canonical_name` (difflib ratio at least 0.85). The match is accepted only if its position agrees with the local offset of the nearest calls mapped by (a) within ±3, or, for (a), if every cited URL is one of the entry's page URLs. Otherwise the call is unidentifiable and skipped. The pages are that entry's `pages`, read from `output/fleet_html/`, each capped at 50,000 characters as 09b did. Recorded per call: the mapping route, the offset check, and the ratio of reconstructed prompt characters to recorded input tokens (across all source-mapped HTTP calls the median is 2.7 characters per token, 5th to 95th percentile 1.5 to 3.4); a ratio far outside that band means the page set may differ from what the model saw, and is flagged.

**What I record by reading the pages** (the capped text, with tags stripped for reading, image alt text and file names kept): every aircraft the school presents as its own or for rent or training, with tail number if shown, make and model, and every posted price for it with its label (standard, club, member, non-member, block, prepay, wet, dry, with or without instructor). Simulators are not aircraft. A tail shown only in an unrelated context (a customer's plane, a news story, an aircraft for sale by someone else) is not the school's aircraft. Listings that look stale (a past date, "sold", "coming soon", "down for maintenance") are noted, not removed. The school: the name the pages give it.

**Scoring.**
- Tails are normalised (upper case, spaces and hyphens removed, leading N added). Correct: a model tail that is on the pages as one of this school's aircraft. False: a model tail that is not on the pages, or is on them only in an unrelated context. Missed: a tail on the pages as one of the school's aircraft that the model did not return. Tail precision = correct / model tails; tail recall = correct / (correct + missed). Rough 95% intervals are Wilson score intervals on the pooled counts. Pooled counts are dominated by schools with big fleets, so precision and recall are also reported per school (share of schools with no false tail, share with no missed tail).
- Aircraft without a tail are matched by make and model within a school; the model's aircraft count is compared with mine.
- Rates: for each model fleet entry with a non-null `wet_rate_hr`, whether that number is posted on the pages for that aircraft (right), posted for a different aircraft or with a different meaning (wrong attachment), or not posted at all (invented); which label the posted number carries; and whether "wet" (fuel included) is stated on the page, implied by context (for example a separate dry price is listed, so this one is the wet price), contradicted (the page says dry, or adds fuel separately), or unknown. The prompt asks only for a wet rate, so every rate the model returned is labelled wet by the schema, whatever the page says. Also counted: aircraft with a posted price where the model returned null.
- School: the model's `canonical_name` is right, partly right (the right school under a shorter, older or parent name), or wrong.
- Empty calls (stratum E) are classified: no fleet listed (the pages name no aircraft the school operates, beyond generic mentions such as "train in a Cessna 172"); model missed (the pages list the school's aircraft); bot wall, error or blank page; or wrong site (parked domain, unrelated business, a directory).

**Limits known in advance.** The sample is 40 calls, so every rate has a wide interval, and the intervals say so. For HTTP calls the page set is reconstructed, not recorded; the offset check and the token ratio are how I test that, and a call that fails them is flagged in the table. I read the same text the model read, not the live site, so "correct" means faithful to the page in March, not true about the airplane today.


## 2. What this means for the talk

- Accuracy, not just consistency: for a random sample, a tail the model returned was on the page as that school's aircraft about nine times in ten. Every tail on the pages was found. Prices were transcribed correctly about 95% of the time.
- Most errors fall into a few kinds, and each one is a single pipeline decision. Flight simulators end up in the fleet (12 of the 21 false entries, tailed or not). Aircraft get read out of URL slugs when the page text is gone (6). Types named in a sentence are promoted to fleet aircraft (3). Separately, one price was copied to the next aircraft. None of these is a misread digit.
- "Wet" is the schema's word, not the site's. Of the 11 sampled schools that post an hourly aircraft price, 7 say the price includes fuel, 1 says dry, and 3 say neither. So a third of the rates the model returned (19 of 55) carry a "wet" label the page never gave. The dry school's 7 prices were left null, which is correct under the schema and loses the prices.
- The empty results are honest: no site that listed aircraft came back empty because of the model. Empties are sites without a fleet list, dead or wrong domains, or pages the crawler emptied (2 of the 4 unreadable sites list a fleet in their raw HTML).
- Stale listings get through: aircraft marked SOLD, "NOT AVAILABLE" or "Unavailable", a 2013 copyright footer. The model copies what the page says, and the page can be years old.

## Deviations from section 1, made after the draw

- **Multi-entry domains.** One domain can have several index entries, one per location page (flightsafety.com has three). The first run of the mapping took the entry nearest the expected position, which gave the first sampled call FlightSafety Dallas South's pages while the model had answered about Denver. The rule now prefers the entry whose pages hold every cited URL, then the nearest. That changed one call's page set and none of the draw.
- **School identity.** The 09c prompt asks for no school name, so "did it identify the right school" is scored in two parts. First, whether the pages are the named school's site at all, for every call. Second, whether the model's `canonical_name` matches, for HTTP calls only.
- **Rate categories added.** "not_aircraft" covers a price the model attached to a simulator. "estimate" covers a per-hour figure from a training-cost table that names no aircraft. "null_dry" counts dry prices the model left null. The schema has no dry field, so leaving them null is correct, but the prices are lost.
- **Raw HTML as a tiebreak.** Decatur Jet Center and Acepilot reached the model as empty or title-only pages, so whether the tails were the school's aircraft could not be told from what the model saw. I opened `output/fleet_html_raw/` for those two calls and for the three unreadable empty calls. Those verdicts are marked in the table. Without Decatur, tail precision would be 68 of 69.

## 4. What could not be scored, and limits

- **Clustered counts.** Tails cluster by school: 75 tails come from 11 calls, and one call holds 6 of the 7 false tails. The Wilson intervals treat tails as independent, so they are narrower than the truth. The per-call lines (9 of 11 calls with tails had no false tail) are the safer reading.
- **Fleet size behind type-level listings.** AeroGuard (120+ aircraft) and Phoenix East (70+) list types only. The model returns one entry per type, so it matches the page while the dataset undercounts the fleet. Untailed recall is scored at the level the page presents (type or aircraft), not against the true fleet size.
- **Pages the crawler did not fetch.** Deer Valley SkyHawks' aircraft list has a page 2 that was not crawled. Anything there is missing from both my list and the model's.
- **Reconstructed HTTP page sets.** The HTTP page sets are rebuilt from the index on disk, not recorded. For the 20 HTTP calls, every offset agrees with its neighbours, and the characters-per-token ratios fall between 0.94 and 3.22, except a 5.72 for a one-page redirect stub, where the fixed prompt overhead swamps the estimate. The low ratios (0.94, 1.45, 1.49) are a one-page prompt and the two prompts that carried binary files. North Coast Air's cited-URL check fails only because the model cited an N146TP detail page that was not among its pages: a fabricated `source_url`.
- **Skipped draws.** 3 of the 43 drawn calls (all HTTP) could not be identified and were skipped under the rule. In two of them, the domain the model cited (1il4.com, midislandair.com) is missing from the index on disk or far from its expected position. These are sites whose entries changed between the 5 March index and the 10 March batch. The skips could bias the sample slightly away from recently re-crawled sites.
- **Binary noise.** In 4 of the 20 HTTP calls, PDFs or a GIF were sent to the model as up to 50,000 characters of binary each. The model's output for those calls was still right, but the noise cost tokens.
- **Not scored.** Airport codes (one is visibly wrong: Flat Lake's PAGQ came back as KBGQ), equipment lists, contacts and `school_type`. The model did type both for-sale domains as defunct.
- **What "correct" means here.** It means faithful to the page in March, not true of the aircraft today. Registry and flight checks are in `docs/hackers-2026-scrape-facts.md`.

OUT=/Users/dew/dev/aether/research/FlightSchoolMapping/output
